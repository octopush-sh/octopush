## Octopush 0.4.153

### Features

- **Choose which MCP servers each crew stage can use** — A Direct stage on the API substrate can now use the MCP servers you choose for it in the stage inspector, from Settings › Integrations only. Each one is off until you turn it on, and a run keeps each server's settings from when it was created. Claude Code and Codex stages keep their own servers for now, and detached runs and Routines run without MCP for now.
- **Read Epiku stories as a project's issue tracker** — Each project can now read Jira, Epiku or no tracker, from its menu under **Issue tracking**. Epiku stories fill the backlog, the ticket chip and the Blocking, Blocked by and Epic pills, and a dotted id like `ST-2.3` in a branch is detected. Octopush only reads Epiku, sending the token and the ids it asks for.
- **Turn a mission's sandbox on or off from the header** — The Shield in the header now toggles the mission's sandbox. Turning it off asks first, because the mission's agents can then write outside the workspace. A read-only mission keeps its sandbox on and says why. A change applies from the next Talk turn or stage.
- **A mission can start after another one** — Choose **Start after…** in a mission's menu to make it wait for another mission's run to pass its last gate, or for its pull request to merge. Then its brief, and the crew of the other mission's last run, wait in Direct for **Begin the run**, unless you turned on **Start the run on its own**.
- **Talk at the keyboard, with Esc to stop a turn** — **Esc** stops the running Talk turn, unless a popover, dialog, approval card, editor or terminal has the focus. **⌘⌥N** starts a new conversation and **⌘⌥K** in Talk switches between them. **⌘⌥A** focuses the oldest approval card waiting in the conversation, so ⌘↵ or Esc answers it; a card never takes the focus by itself, so a stray keystroke can't answer a command you haven't read.
- **Allow a folder or a command for the conversation** — An approval card in Talk can now keep a narrow grant for the conversation: **Allow writing** a folder outside the workspace, or **Allow this command**, exactly as written. Credentials locations always ask, a command that changes something outside this Mac is never allowed this way, and Plan only applies none.
- **@ can name an earlier conversation or a definition** — In Talk, `@chat:` attaches another conversation of the same workspace: its summary when it has one, otherwise its asks and last answer, capped at 64k and checked for secrets. `@` followed by a name also lists where the workspace defines it, and choosing one attaches those lines.
- **See what each Talk turn changed, and review it alone** — A Talk turn that changed files now ends with a row: how many files, the lines added and removed, and their names. **Review these changes** opens Review on that turn's diff alone; `x` reverts a hunk in the working tree when it still applies cleanly. **Rewind files to here** is one click away.
- **Test a ticket in a workspace that ships nothing** — Choose **Test a ticket** in the new-mission wizard, or **Test this ticket** in a backlog ticket's menu. Talk's agents build and run the ticket's branch locally, and Octopush refuses the git pushes, pull requests and publishes their commands ask for. Talk runs plain commands only there, without your shell profile's aliases and functions, and ssh, scp, rsync and deploy CLIs aren't checked yet.
- **Each workspace gets its own block of ports** — Every workspace now has its own 10 local ports, shown at the end of the header. Its Run terminals and Talk shell get `OCTOPUSH_PORT` and `OCTOPUSH_PORT_COUNT`, so each workspace's dev server can use its own port instead of colliding. Setup scripts written for Conductor get `CONDUCTOR_PORT` too.

### Improvements

- **A project's MCP servers start only after you approve them** — A server in a project's `.claude/mcp.json` now waits for your approval in Talk, which shows its exact command, arguments and env names. Any change to its entry asks again, and a project server never replaces one of yours with the same name. A change to `.claude/mcp.json` or Claude Code's `.claude/settings*.json` by an agent always asks.
- **See and revoke the project MCP servers you approved** — The Companion lists the servers a project's `.claude/mcp.json` defines, with whether each is approved, waiting, changed since you approved it, or replaced by one of yours. Settings › Integrations lists every approved one. Revoking stops the server, and it asks again before it starts.
- **See and turn off skill shell commands in crews** — The Direct launcher now lists the shell commands a repo's skills and commands run as they load. **Don't run skill shell commands in crews** turns them off for the project's crews and Routines, your own and plugin skills included, and each stage's launch line records it.
- **Talk's error card says what failed and what to do next** — When a Talk turn ends on an error, the card now says what happened and how much of the turn was kept, with one action: **Try again** after an overload or outage, **Configure API key**, or **Copy error details**. A spend-limit 429 or an error the provider marks final now shows at once instead of after minutes of retries.
- **Talk chats get short titles after the first answer** — After its first answer, a Talk chat is titled in a few words by the fast tier of the provider it already uses, led by its ticket key when it names one, and billed to the chat. Until then, and whenever no title comes back, the title reads the message without skills, mentions or long URLs.
- **Talk remembers the images you sent** — An image you attach in Talk now stays in the conversation, so a follow-up can ask about it without sending it again. Images are kept on this Mac and go only to the conversation's model. In a very long conversation the oldest images are left out first, and deleting the conversation, its workspace or its project deletes them.
- **Fewer MCP approval cards in Talk** — In Edit freely, an MCP tool whose server marks it read-only or not destructive, or whose name starts with a read verb such as `get_`, now runs without a card. Names and hints are the server's own claims. The card can also allow a tool, or trust a server from Settings, in every conversation, until you revoke it or change the server.
- **A new Talk conversation offers a place to start** — A new conversation offers three starters: **Review what changed**, **Ask about a file** and **Explain this workspace**. A stopped turn now says its changes stay and how to rewind them, and a turn cut off by an app restart says so.
- **Talk reads a file before it overwrites it** — The agent now sees line numbers when it reads a file, so it can cite `path:line` and aim its edits. It can no longer overwrite an existing file it hasn't read, or one you changed after it last read it: your edits made while a turn runs stay. Sub-agents and API crew stages follow the same rule.
- **Test an Epiku story like a Jira ticket** — **Test this ticket** now works on Epiku stories too. The mission starts from the story's branch when one exists, and its brief carries the story's text as plain text, ready for a crew to verify locally.

### Fixes

- **Cut-off rounds retry cleanly on thinking models** — When a Direct stage or a Talk sub-agent hits its output limit in the middle of a tool call, the retry now keeps the round's thinking. On models that think with a budget, such as Haiku 4.5 and Opus 4.5, that retry no longer fails with an API error.
- **Fast-mode Fable 5.2 turns are priced at $16/$80** — Claude Code fast-mode turns on Fable 5.2 and Mythos 5.2 now cost $16/$80 per million tokens in Usage, twice their standard rate, with cache reads and writes doubled too. Before, they showed as **unpriced**.
- **Broken tool arguments are sent back, not run** — When an OpenAI-compatible or local model sends tool arguments that aren't valid JSON, Talk, Direct and sub-agents no longer run the tool with empty input. The model gets the parse error and the start of what it sent, and can call again.
- **A .env that is a named pipe no longer hangs a read** — Opening or `@`-mentioning a file that is a named pipe, socket or device, such as a `.env` served by a secrets manager, now fails at once with a plain message instead of hanging the editor or Talk.
- **Sandbox catches protected names written with ligatures** — A sandboxed Codex stage can no longer write a protected file in a Codex home by spelling its name with a ligature such as `ﬁ` or `ﬆ`. The volume treats those as the plain letters, and now the sandbox does too.
- **Sub-agents count a failed run's spend and stop at budget** — A sub-agent that fails after real work now bills it: the ledger, the thread and your budgets show what it spent, and you can continue it from its journal. With a budget set, each sub-agent stops at its share of what is left, retries and extra turns included, and an agent file's `max-cost: 0.50` caps that type's runs.
- **Talk keeps the end of a long command's output** — When a command in Talk prints a lot, the agent now sees its first and last lines, and more of the end when the command fails, so the failing test and the summary are no longer lost. It can read the whole output, up to 4 MB, without running the command again. Error lines now appear in the order the command printed them.
- **Talk stays within each model's output limit** — Talk, Direct and sub-agents no longer ask a model for more output than it takes, so GPT-4o and DeepSeek Chat stop refusing Deep turns. An answer cut at the output limit now says so: say continue to get the rest. Two replies in a row cut mid tool call end the turn instead of retrying.
- **Stop ends a running tool in Talk** — Stop in Talk now ends a command running in a sandboxed mission, or in the isolated shell used while the shared one is busy, within a second, and ends a long grep or glob. A long search in one workspace no longer slows the conversations of another, and reading part of a large file no longer loads all of it.
- **Stop during a crew keeps the reports already in** — Stopping a Talk turn while sub-agents run no longer drops their work. Every report that came in stays in the thread and in what the next turn reads. A sub-agent cut off reads as stopped, and you can let it finish from its journal.
