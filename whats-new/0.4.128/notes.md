## Octopush 0.4.128

### Features

- **See when two workspaces change the same files** — Octopush now notices when two live workspaces of a project change the same files, before the merge does. An amber mark means a file overlap, rouge means the branches will conflict. It only warns and never blocks anything.
- **See each settled crew's diff size in Mission Control** — Settled and needs-you cards in Mission Control now show the size of the crew's diff against its base branch, like `+120 −40 · 6 files`. The Settled band can be ordered **Smallest first** as well as oldest first.
- **Jump to any workspace from ⌘K** — ⌘K now has a **Workspaces** group: one row per workspace across all your open projects, with its project and branch. Workspaces waiting on you come first, then working ones, then the most recent. Picking one switches to it like a click in the rail.
- **Crews wait out your Claude plan limit and resume** — When a Claude Code stage hits your Claude plan's 5-hour or weekly limit, the run now pauses at the stage boundary and resumes the same session after the window resets, even with Octopush closed for detached runs. Mission Control shows it in flight as `plan limit · resumes 19:40`. Routines skip a window while the plan is at its limit.
- **Quiet Claude Code in crews and Routines** — A new Settings › Privacy toggle, off by default, starts Claude Code for crew stages and Routines with `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, so it skips its auto-updates, telemetry, error reporting, release notes and availability checks. Features that need feature-flag fetching, such as Remote Control, don't work in those sessions. Run terminals are not affected.
- **Octopush stops your keys at commit, push and PR time** — When you commit, push or open a pull request in Octopush, it checks the change for API keys, tokens, private keys and the keys you saved here. A finding asks you first, and a crew stops before its pull request, merge or release stage until you decide. An agent's own shell commits aren't checked yet. Nothing leaves your Mac, and the value is never shown.

### Improvements

- **Know when Codex will skip your repo's .codex/ settings** — When a crew has a Codex stage and the repo has a `.codex/` folder that Codex won't load because the project isn't trusted in Codex, the Direct launcher and the stage journal now say so and how to trust it yourself.
- **A sandboxed stage says which write dirs it left out** — When the sandbox leaves out a dir such as `~/.claude/projects` because it points somewhere unsafe, the stage's launch line now says which one and why. The sandbox also refuses more unsafe places, such as a dir that points into `~/.config` or `~/.ssh`.
- **Sandboxed stages write less of ~/.claude** — A sandboxed stage now writes only the parts of `~/.claude` (or your `CLAUDE_CONFIG_DIR`) that hold Claude Code's session state, not its skills, agents, plugins, hooks or settings. Auto memory is off in sandboxed Claude stages. The shared `~/.cache` isn't writable either: pre-commit, uv and similar caches use the stage's own build cache, so they start cold once per workspace.

### Fixes

- **A stage waiting out an API retry is no longer stopped** — A crew stage waiting out an API retry is no longer stopped as stalled. When Claude Code says it will wait before retrying an overloaded API, the stage gets that wait, up to five more minutes, on top of its usual five minutes, and a stall after a retry now says so.
- **Chat titles use the whole row** — In Talk's Chats list, the row actions no longer hold empty space while hidden, so each conversation title uses the full width of the Companion before it wraps. Hovering a row now fades its actions in over the end of the title instead of pushing the title aside, so it never rewraps under your pointer.
- **Claude Code 2.1.325 recommended for its sandbox fixes** — Readiness, the Direct launcher and stage journals now recommend Claude Code 2.1.325, which stops the Bash sandbox switching off mid-session and protects a worktree's settings, hooks and shared git folder. If Claude Code refuses a stage's settings at start-up, the stage now names the refused setting.
- **One journal line for a resumed Codex stage's usage** — When a resumed Codex stage can't count its usage exactly, the journal now says why once, instead of also adding a generic "cost is unknown" line.
- **Crew stages on gateway models compact before they fill** — Crew stages on gateway models compact before they fill instead of failing every turn. When a Claude Code stage runs a model from your own provider entry with a smaller context window, Octopush now tells Claude Code that window. Set the real context window in the model's entry under Settings › Models; a new entry starts at 200K.
- **Shortened names read as one piece again** — When a long name is shortened in the middle (rail rows, project names, branches, file paths), the ellipsis now sits right against the end of the name, with no stray space or gap that changed from row to row.
- **Long project names fit in Project links** — In Settings › Integrations, a long project name in Project links is now shortened in the middle with an ellipsis and keeps its distance from the Project key field, instead of running under it.
- **A running stage no longer looks like it needs you** — On the Direct run track, the stage that is working now keeps its verdigris edge and pulse. Brass is left to a stage waiting at a checkpoint, so working and needs-you no longer look the same.
- **See when a stage ran on another model** — When Claude Code's settings run a crew stage on a different model than the one it asked for, the stage card and the run ledger now say "ran on …", the journal says why, and the stage's cost and savings are counted for the model that actually ran.
- **Stopped Claude stages price subagents at their own model** — When a Claude Code stage is stopped before it finishes, its estimated cost now prices each message at the model that answered it, so a subagent on Haiku or Sonnet is no longer billed at the stage's Opus rate. Usage with no price now reads "+ usage not reported" instead of $0.
- **The welcome screen's main action leads again** — "Set a crew on it" now keeps its framed primary look in every state, even before you type a brief. Its lettering turns full brass once a brief and a key are in place, and stays softer, though still clickable, while a key is missing. The quieter routes beneath it share one ink and one underline, and turn grey while they're unavailable.
